Generate a production-grade Claude Code slash command named "/analyze-then-pick". It must always remain a normal Claude Code command and must never be created, executed, interpreted, delegated, converted, or triggered as a Claude Code workflow. Do not create or invoke workflows at any point. Keep analysis agents minimal: none by default, one when there are many reference videos, and at most two for a large folder. In Analyze Mode, production is the exception. Every video is produced end to end (Higgsfield generation, then CapCut editing) by its own agent, with at most five agents running at once, so that no video waits behind another. Agents never overlap, never ask the user questions, and report blockers back to the main session.

Before building the command, research the official documentation, engineering papers, product documentation, prompting guides, technical references, examples, model cards, API documentation, and first-party prompt examples for the video-generation models available through the intended Higgsfield MCP environment. Research Higgsfield and Higgsfield MCP as well, including supported models, generation and editing operations, references, image-to-video, video-to-video where supported, character consistency, product or object references, camera controls, motion controls, duration, aspect ratio, resolution, start/end frame functionality, supported inputs, model limitations, prompting behavior, and official examples.

Include how prompts should be structured, how the model interprets subject, action, environment, chronology, camera, movement, references, style, continuity, physical interactions, negative constraints, visible text, character consistency, product or object fidelity, known strengths, weaknesses, failure modes, and relevant model-specific features. Knowledge packaging: a router command, phase skills and section files. The context of a run is its scarcest resource, so a step must never load text that only a later step needs, text that belongs to the other mode, or a document as a whole. Package the pipeline as follows (this is how the library is built today):
- **The command is a router.** `~/.claude/commands/analyze-then-pick.md` (about 13 KB, the only file loaded when a run starts) holds the arguments, the resume check (read `state.json`, invoke the skill named by `next_skill`, or derive it from `stage` and `next_step` for a run made before this layout), the routing of a reported wrong video to the feedback skill, the loading rules, the operating contract as one line per item (the shortest items verbatim), the phase map with each phase's skill and next skill, the order of the per-video loop, the labels table (A1, E1, X1, item N and so on, each pointing to the skill that owns it) and the global Never rules, and it allows the Skill tool.
- **One skill per phase**, at `~/.claude/skills/atp-*/SKILL.md`, each `user-invocable: false` with a short description marked internal to the command (so none fires in an unrelated session): `atp-start` (mode, sub-mode, the model menu and lock, inputs, the run), for Analyze Mode `atp-analyze-prepare` (inventory, preprocessing, documents, guardrails, asset registry), `atp-analyze-study` (video analysis, synthesis, house approach, the count), `atp-create-plan`, `atp-recreate-plan`, `atp-asset-plan` (asset plan and the long-video permission) and `atp-analyze-produce` (prepare every video, spawn the production agents, handle their reports), for Edit Mode `atp-edit` (intake to the per-edit review), for the per-video loop `atp-plan-video` (X1), `atp-write-request` (X2), `atp-inputs` (X3), `atp-precheck` (X4 to X6), `atp-submit` (X5 again and X7, with the flag recording), `atp-postprocess` (X8, with the CapCut assembly), `atp-qc` (X9) and `atp-record` (X10), and `atp-wrapup` (the wrap-up and the Topaz upscale), `atp-feedback` (a delivered video reported as wrong) and `atp-model-guide`. Each skill carries, verbatim, the steps, the contract items and the Never rules of its own phase (a rule that two phases act on is written in both), a "Read now" list that names the exact section files the phase needs with their conditions, its own definition of the paths and the citation convention (agents never see the command), and a hand-off that records `stage` and `next_skill` in `state.json` and names the skill to invoke next. After a compaction, or on resume, the skill in `next_skill` is invoked again, so every phase boundary is a safe cut.
- **Section files.** Every long document (the nine references, the Higgsfield MCP guide and every model guide) is an index file (its preamble plus a generated table of section number, title, file and size) and a folder of section files named `<seq>_<id>_<slug>.md`, cut at the headings and only where a section exceeds about 8 KB. The section numbers (§4b.1c, §2.14, guide §3.14) never change, so every citation still resolves through the table, and a citation whose id is not a row lives in its nearest parent row. A deterministic tool, `scripts/docs_tool.py`, splits a document (losslessly: it verifies the rejoin byte for byte), joins it, rebuilds its index, checks the whole library (indexes against files, skills against the skill names and paths they cite, every section citation) reports what each skill loads and which section citations a skill makes that its own Read-now list does not load; only `/update-from-errors` ever reads a whole document.
- **One engineering guide per model, not one skill per model.** Each generation model's researched guide (written on the fixed template, every claim tagged official, Higgsfield, secondary or inferred, with the verbatim official examples and their patterns, the 9:16 720p mapping, text handling, integration and continuity phrasing, how counts and the use of every part are phrased, failure modes and the checklist) is stored as an index plus section files under `models/<guide>/`. The model index (`models/index.json`, about 40 KB, never read whole) maps model ids to guides and capabilities, and `atp.py model-entry --id` prints one model's entry with its guide folder. `atp-model-guide` holds the table of which sections each step reads (the request: call recipes, the 9:16 mapping, structure, references, negatives, text, product fidelity, integration, the official examples and the section of the request kind; the pre-generation check: the failure table and the checklist; the submission: parameters, durations, gotchas; the QC: the failure table) and how to add or update a model. The guides of other models are never loaded and a guide is never read whole. A model's first-party prompt optimiser (the existing `sd25-pe` skill for Seedance 2.5) is wrapped or cited by its guide, never duplicated. A skill per model was rejected: every skill's description sits in the skill list of every session on the machine, and one router skill plus sectioned guides gives the same read-only-the-locked-model behaviour at no listing cost.
- **No registration in the global CLAUDE.md.** The harness lists the phase skills itself, and anything added to the always-loaded global file only adds rot; the global file keeps the user's own standing instructions.
- **The production agents' contract** is generated for every run from the canonical prompt in the production-agents reference. It names the per-video skills in order (inputs, submit, postprocess, QC, record; the request and pre-check skills only when a request is rewritten), with the fallback of reading the skill file by its path when the Skill tool is unavailable, and it forbids reading the command, a whole reference, a whole guide or the model index.
- **Other knowledge collections** (the Higgsfield MCP guide, the analysis protocol, the generation system, the anomaly catalog and its QC stack, CapCut assembly, the text policy, the asset and substitution rules, the production-agent contract, the creative direction, the brand guardrails and any later collection of data, instructions or quality-control rules) are section-file documents read at the step that names them; plain data (the model index, catalog snapshots, the house approach, the registry and ledger formats) stays in plain files.
- **Extendability.** Adding a model means researching it on the template, splitting it with the tool, adding its index entry and its menu position; updating one means bumping its version and last-verified date and re-indexing. Adding a phase means adding its skill with its hand-off, its row in the router's phase map and labels table, and running the library check, which must report no errors.

When "/analyze-then-pick" runs, first ask whether the user wants Analyze Mode or Edit Mode.

When Analyze Mode is chosen, ask next whether to Recreate or Create. The two are never mixed:
- **Recreate.** After the analysis, the agents autonomously edit X of the original reference videos with the client's assets. The user gives X, and the agents pick the best-fitting references. The scenario stays the same: people are swapped to the supplied characters, and the product is swapped, filled into a vessel or placed. It works like Edit Mode, but it is fully autonomous and uses the assets given at the start, with no per-video questions or reviews. The agents pick under the client's guardrails (see "Brand guardrails" below): a reference whose core a rule bans is dismissed, a reference with a peripheral hit is picked and edited. The user still picks the model, for example Seedance 2.5, Seedance 2.5's edit mode, Wan 3.0 Prime or Kling. The output is the source with only the planned operations changed: every other movement, action, detail and timing stays as it is, the reference's own audio returns under the edited picture, and a sync check confirms that every action lands on its sound (see "Source fidelity" below).
- **Create.** The agents generate N new videos: varieties that exploit the patterns, styles and content types that made the references go viral, in one style group or a mix of style groups that the agents suggest, for example "organic × style × subject" and "anime × style × subject" groups. Each variety is its own concept (a different scenario, hook or setting), and the client's product is blended into it through its most natural use. No reference video, frame or clip is ever edited or used as a generation input. Create never repeats what a reference shows: the analysis collects how each reference is made (its style, its properties, its approach, its crafting, its hook logic, why it works) and Create makes another video with that craft and a new subject and a new idea; restaging a reference's scene is Recreate's job and a failure in Create (see "Transfer, not repetition" below).

Immediately after the mode is chosen, ask which video-generation model to use for the whole run:
- Show a numbered list of every video-generation model currently available through Higgsfield. Never show a shortened list, even if it takes up much of the console view.
- Pin Seedance 2.5 and Wan 3.0 Prime at the top, and give short notes on what each model can do and how well it fits the chosen mode.
- The chosen model is locked for the entire run. Never ask again, switch it, or suggest switching it; only an explicit user request changes it.
- If a later step needs a capability the locked model lacks, adapt the approach within that model (for example, build a start frame from the supplied assets or split into clips) and state the adaptation in the brief.

Brand guardrails. The assets folder usually holds documents with the client's rules: a brand book, dos and don'ts, a legal or compliance note, a claims policy, a list of people whose likeness may not be used. They decide which references may be picked and what must change in them, by one principle: if a reference's core is what a rule bans, it is not picked; if the rule hits something an edit can change without changing what the video is about, it is picked and edited. For an energy-drink client: "no blood or gore" dismisses a reference whose prank is the gore, and removes a horror poster from one where it is set dressing; "no excessive-caffeine messaging, two cans per day max" reduces three cans on a desk to two and dismisses the reference whose joke is twelve cans; "no competitor brands on screen" de-brands a Red Bull or Monster in frame (the name, the logo and the identifying trade dress removed, the object kept as a plain one of the same shape, size, spot and light, never blurred, pixelated or covered), leaves a bag of Doritos alone because it is not a competitor, and dismisses a taste test between competitors; "no ambassador likeness" picks the reference and swaps the face without exception, as every person is swapped in Recreate, while a hook that names the ambassador dismisses it; for an adult-only audience (a client rule, or an energy drink) a caption that implies a parent or a school is rewritten into an adult register with the joke kept, characters who read 20 or older are cast, and a reference whose premise is a minor's life is dismissed. The pipeline therefore:
- reads every document among the assets and the references, extracts each rule into a guardrails file (the quote, its source, its kind, what it hits, its default operation) and derives the lists the rules imply: the competitors (named, plus every brand in the client's product category), the excluded people, the count and context limits, the banned wording and required disclaimers, the presentation rules; conflicts between documents or with the user's instructions go to the user once, with both quotes, and no rule is ever invented;
- audits every reference against the rules on its analysis card: each hit located (time, element, prominence, whether it sits in the picture, a caption, the speech, an insert or a reflection) and classified core (the hook, turn, payoff, subject or premise depends on it; it is spoken in audio that returns under the edit; a hand or the action touches it; removing it would break a beat or the sync; the edit would change what the video is about or where it goes) or peripheral (set dressing, an untouched unit beyond the limit, a brand mark on an object that stays, a person who is swapped anyway, a caption line, a segment a cut can drop), with the meaning test deciding: would a viewer who never saw the source describe the edited video the same way, and does the sync still hold; the verdict is pick-clean, pick-and-edit with the operations, or dismiss with the rule;
- in Recreate, applies the audit as the first filter of the ranking, lists the dismissed references with their rule, carries the operations into the pick's source action script, its edit load and its first request under the fidelity lock, and holds a reduced count at every checkpoint of the ledger; in Create, turns the rules into plan invariants (the count limit in the ledger, no competitor objects, supplied characters only, the wording rules in the text plan, the presentation rules in the anchor and the use beats, and a seed that a content or context rule hits scores zero on brand safety); in Edit Mode, shows every hit with the operation the rule requires, or states that a core hit cannot be edited without changing the video, and leaves the decision to the user;
- edits in the model's own grammar: remove only the extra unit and reconstruct the surface; remove only the name, logo and markings from the competitor's object and keep it; the person-replacement contract for an excluded person, complete across face, hair, marks, reflections and mirrors, with an insert that shows them cut and not placed back, their name dropped from the text and their voice named in the brief when the original audio returns; a caption that breaks a wording rule rewritten minimally in CapCut in the same role, position and timing; a required disclaimer added as a text layer in the house style; a printed surface of the source that a guardrail names (a news page on a monitor, a poster, a livery, a gate board) replaced by a named concrete thing in the same edit grammar, with the original item in the exclusion line, never described as blank or plain or left unnamed, because those came back printed in the first requests;
- verifies at quality control: the count at the limit at every checkpoint, no competitor name in the text detection and no logo, claw, crest, livery, blur or patch on any de-branded object at full resolution, no printed surface a guardrail named reproduced (text detection at full resolution; a reproduced one is a regenerate reason and the retry names the concrete replacement), the excluded face absent from every shot, reflection and placed-back insert, the rewritten lines and disclaimers on the CapCut preview; a leftover hit in the picture is a regenerate reason, in a text layer a CapCut fix; and the wrap-up names the guardrails applied, the references dismissed with their rule and the edits each pick needed.
The user's run instructions outrank the guardrails; the guardrails outrank the house approach and the pipeline's defaults; and they never relax physical and logical correctness, the must-not-survive list, the permission rule, the house text style or the model lock. Without a guardrail document, only the copyright and ownership floor and the generation service's blocks apply; the pipeline has no content rules of its own and never blurs, softens or removes content for taste.

No error ledger: the rules live in the pipeline. There is no caught-errors file, no toolkit command that records errors and no per-run digest of past errors, and nothing in a run reads an error file, because a growing pile of past errors read at every run start rots the agents' context (a run writes only a video's own attempt block in its brief and result file and the Higgsfield flag record described below, and no later run reads them). Every lesson learned from a video that went wrong (a user's report, an agent's regenerate reason) is written, generalised, in the section that owns it, in the references and the model guides: as a kind (what to achieve, what to avoid) with the miss, its cause, the corrected wording and what worked as the sample beside it, and CE-nnn case labels in those files mark the lessons (the README explains them; the library's learning log maps each label to its section). When the user says a delivered video is wrong, in the run or in a later session, the command takes their words verbatim, diagnoses them in pipeline terms (the stage that made the miss and the stage that should have caught it), says which section already holds the rule and why it did not prevent this video, and offers the fix (a re-edit or a regeneration of that video in its mode); when the miss is a kind the references do not hold, it says so in one line and names the companion command with the user's words as its argument. A user's word outranks the agents' quality control on the same point, because the user saw what quality control passed. Production agents write a regenerate reason or a flagged delivery in the video's brief (an attempt block with the failed request, the verdict with its numbers and frame paths, and what the retry changes) and in their result file, nothing else is written to the library but the flag record, and the main session checks, as each agent reports and in the wrap-up, that every regenerated or flagged video has such a block. Edit Mode's "needs changes" writes the user's words and the diagnosis in the brief before the re-edit, and a message that opens with feedback about a delivered video is handled before anything else. Once every video is delivered, the wrap-up asks the user for feedback ("all good", "I'll watch them later", or which video is not right and why), and each problem named, then or later, is handled as above before the fix is offered. After the feedback question, once the generated videos and the editing are done, the wrap-up offers to upscale the final videos 1.5x with the user's Topaz script, and runs it only on the user's explicit yes: in Edit Mode on the final folder, in Analyze Mode on the folder the user exported the CapCut projects to (asked for, never guessed; the clean generations are not the finals). On a yes it runs, in one PowerShell call, exactly these two commands with the folder filled in: cd "$env:USERPROFILE\Scripts" and then Get-ChildItem -Path "<folder>" -Filter *.mp4 | Where-Object { $_.Name -notmatch '_[\d.]+x\.mp4$' } | ForEach-Object { .\topaz-upscale.ps1 -InputFile $_.FullName -Scale 1.5 -Yes }; the filter skips files already upscaled so a rerun is safe, the script writes <name>_1.5x.mp4 beside each source, and the wrap-up reports the upscaled files and any failure with its real error (ffprobe on PATH and the Topaz API key are the two prerequisites) without retrying on its own. On "not now" it only prints the two commands. A companion command, /update-from-errors, takes the name of a command (here analyze-then-pick) and improves that pipeline in one pass from the errors it is given: the user's words as its argument, the briefs, request files and result files of the runs (the run-level records of something going wrong, each with an id of its own), and any file that holds errors under another name; one error in several files is one row with all its sources named, missing fields are marked not recorded and never invented, and the scan's result is part of the report: it first reads and models the whole pipeline (the command, its references, the guides of the models involved, the toolkit, the memory and its own learning log), and only then reads every entry, checks each diagnosis against the brief, the request and the evidence still on disk, places each error on the stage that made it and the stage that should have caught it, clusters the entries by what really failed, reverse-engineers each cluster (where intent and output parted, which lever caused it, why the rule in force did not prevent it, what worked), generalises each lesson into a kind that fits other products and scenes (what to achieve and what to avoid, written without the entry's product, brand or scene; the miss and its cause; the prompt correction; what worked; a transfer test against two other products or scenes), grades each lesson by its evidence (proven by a verified prompt or the user's approval, repeated, single, model limit, false positive), checks for each lesson whether the pipeline already holds a first-try rule, an error definition with a threshold and a measurable quality-control check for it, and the lesson itself in that general form, and, only for the gaps (a rule that exists only as an instance is a gap of form, repaired by replacing its wording), rewrites the owning sections: the first-try prompting in the model's phrasing, the use cases and dismissals, the craft guidance, good and bad samples that carry the miss and its cause (the good side only from a prompt that passed), the error definitions and the measurable quality-control checks with their thresholds. The pipeline's architecture and structural design are never changed by it: what exists keeps its place, its role, its name, its interface and its cross-references, the stages stay in their order, the files keep what they own, the agents keep their contracts, the toolkit keeps its commands and flags, and formats and the run layout stay as they are. Whoever made the call, an agent or the main session, in both modes, records the flag at once and before the request changes, only through the toolkit (never by hand, so the ids and the format stay parseable): the submission is marked flagged in the run's submission ledger, then a flag entry is added: the script gathers what the run already knows (given the run, the video and the attempt: the request's prompt and parameters, every input with its file, type, reference or asset id and a thumbnail, the reference video and the source segment it covered, the plan and the brief, and the job and fingerprint of the ledger row marked flagged), and the recording agent supplies the judgement: Higgsfield's response verbatim (or the words none given), the kind, the tool and the stage, the credits refunded, its suspected trigger labelled as evidence or inference, one to four grouping tags for the trigger (a real person's face, a celebrity name, a brand name, protected IP, an nsfw image, a video reference, a preset notice, an unknown trigger and similar) and, when it can tell, which input caused it, the exact words of the prompt and which seconds of which video; the script only gathers, records and tabulates, never guesses, and lists what was not given. The agent then makes the one diagnosed change, records what changed, and marks the entry cleared only once a changed request was accepted, attaching the accepted request and job and receiving the sentence-level difference from the flagged prompt; a flag that stays is marked persistent and the video is planned another way or reported; after two identical refunded flagged failures a third identical request is never sent (the plan drops the trigger, for example the video reference, and says that fidelity and sync are at risk), and a flagged asset or video is never re-uploaded unchanged. The page is written, never read: no step of a run, no plan and no agent contract opens it, and no digest or copy of it is made, because a growing file read at every run start rots the agents' context; what a flag teaches is held as a general rule in the references (the moderation fallback in the generation system reference, the model guides' failure tables, the Higgsfield guide's error table), and the pre-generation check tests the plan against those rules, planning the fallback request before the first submission when a trigger cannot be avoided. The main session runs the toolkit's reconcile command as each production agent reports and in the wrap-up, which lists submissions marked flagged that have no entry and failed submissions to judge, so no flagged call leaves the run unrecorded, and the wrap-up reports how many flags were recorded and how many cleared or persisted, naming each persistent one. The user opens the page with the toolkit's open command to see the flags grouped by trigger tag, suspected asset, video, kind, run or model, and searches them by field. The page starts with the two cases the pipeline already met: the celebrity face in a video reference that made two jobs fail within seconds with no reason, and the recurring preset recommendation notice returned instead of a job.

For video preprocessing, prefer a deterministic local pipeline such as FFmpeg for metadata inspection, frame extraction, temporal sampling, audio extraction, scene inspection, and related processing unless another available tool provides a meaningful advantage. Explicitly record the chosen processing pipeline inside the command documentation.

Extract and inspect video frames at approximately 5 frames per second as the default analysis sampling rate. This provides enough temporal detail to understand actions, product appearances, character movement, hooks, transitions, object interactions, scene continuity, and other important changes without requiring inspection of every native video frame.

The 5 FPS rate is a default baseline rather than an inflexible rule:
- Temporarily increase the sampling density around fast actions, cuts, transitions, object swaps, product interactions, important gestures, text appearances, or other moments where more temporal precision is required.
- Reduce the density for long static sections when additional frames provide no new information.
- Do not perform five repeated analyses of every individual frame. The rule is approximately 5 extracted frames per second of video, with adaptive sampling when useful. The frames are read as labelled contact sheets of 30 frames each (six seconds at 5 fps; about one second of a 30 fps checkpoint in quality control, longer spans split into balanced pages), and every sheet is sized within the vision model's limits (at most 1.15 megapixels and 1568 pixels on the long side) so that it is read at full size and no cell is shrunk; a larger sheet with more frames only comes back downscaled and makes every item in it smaller.

Analyze audio, dialogue, scene structure, metadata, and important temporal events alongside the extracted frames, so that the video is understood as one continuous sequence rather than as unrelated images.

In Edit Mode and in Analyze Mode's Recreate, the videos are uploaded as edit sources. So at intake, extract the audio of every original video in the given path (for example "C:\Users\Glaresquare1\Documents\celsius\22.09"):
- The audio goes into a new folder inside that path named "files_audio".
- A silent copy of each video goes into a new folder inside that path named "videos_without_audio".
- The videos in "videos_without_audio" are the ones uploaded to Higgsfield as the source or sample when swapping, replacing or otherwise editing, because silent uploads have a lower possibility of being flagged. The same applies to any reference video uploaded as a motion or camera reference. Never upload an original video with its audio.
- Analysis still uses the originals, with audio.

In Analyze Mode's Create, the videos' audio and content are fully processed for the analysis (frames, on-screen text, transcript, loudness, music and sound cues). The audio of each reference is also extracted into "files_audio", but no silent copies are made, because no reference video is ever uploaded or used as a generation input. The extracted audio serves the sound design.

Sound design in Create:
- **Why.** A Higgsfield-generated video usually carries only the characters' voices, movement sounds and ambience. TikTok and Instagram Reels usually add audio that fits the video: a dramatic track, a soundtrack, sound effects, or all of them.
- **Analysis.** For every reference, measure its sound design: whether a music bed is present, its tempo, beat strength and energy arc, the hits or stings and whether they land on cuts, the share of speech, and whether the sound is free of speech and so reusable as a whole. From these measurements and the visuals, infer the sound's role: dramatic, comic, suspense, hype, or driven by sound effects.
- **Generation.** Each Create video is generated with dialogue, action sounds and ambience only, with no generated music.
- **Sources for the soundtrack and effects, in this order:**
  1. a track the client supplied;
  2. the reference's own sound, when it has no speech over it;
  3. a matching royalty-free or Creative Commons track found by mood, genre and tempo and downloaded, with its source and license recorded;
  4. for sound effects, the bundled royalty-free library or downloaded equivalents.
- **Licensing.** Audio with an unknown license is never used. Reusing a reference's sound is marked for the user, because the rights belong to its owner.
- **Placement.** The soundtrack and the sound effects go on their own audio tracks in the video's CapCut project. The music sits lower under speech and drops under meme inserts so the meme's sound wins. The effects sit on the new video's cuts, reveals or punchlines.

Understand each video as a full temporal sequence rather than independent frames. Determine what happens from beginning to end, what the subject is, what is being communicated, what objects or entities matter, how the scene evolves, what is said, how the user is addressed, what the payoff is, how camera and editing behave, and how earlier actions logically affect later ones. Analyze spoken audio when useful. For every handled object, record how it is used (the part used, such as the spout, the opened top, the nozzle or the torn end; the preparation step; the contact point; the hand; the head angle) and the count of every multiple over time, because a Recreate keeps them and a Create reuses the mechanism; note the source's own count or affordance breaks so they are never copied.

The pipeline is also the creative team. It acts, at once, as a social-media and product-growth creative specialist (what stops a scroll, keeps a viewer, earns a share or a comment, and makes a product remembered without being sold; platform mechanics such as the first second, the retention curve, the loop, the comment bait and the native look), a mass-cognition engineer (how a broad audience perceives in the first second and feels across the clip: instant recognition, cognitive ease, the curiosity gap, the pattern interrupt, relatability and identity, the emotion arc, the mechanics of a laugh, the "send this to…" reflex), a trend analyst (the references read as a trend corpus: format names and caption grammar, structural mechanisms that outlive a trend versus surface elements that date, freshness judged from the material, and at most two bounded web checks per run when a decision depends on whether a format, meme, sound or caption convention is still current), a creative director (many ideas, scored, the sharpest picked, the bland killed, every video distinct, the best approach chosen for the goal) and a performance editor (the hook in the first second, the payoff on the family's beat, the loop, the text as a hook, the sound as a lift). Concretely:
- **Goal model.** Every run writes its goal in one line (awareness and product memory by default; consideration, a conversion cue or community and shares when the user or a document says so) and every video gets a job: what the viewer does at the end and what they keep of the product. The goal changes which references, mechanisms and concepts win; it never changes a hard rule.
- **Audience model.** Who the references speak to, the cues that reveal it, and what that audience recognises instantly; every video is built on a situation they have lived and surprises inside it, names its emotion arc at the hook, the middle and the payoff, says which laugh mechanism it uses (incongruity, escalation, callback, timing, deadpan, reversal), keeps the product's mark readable at the moments of highest attention without featuring it, and has a share line a viewer would type when sending it.
- **Trend read.** For each family: the format names, the structural mechanisms, the surface elements marked current, fading or dated; structural mechanisms are reused freely, surface elements only when current and needed by the family's language, dated ones never; a Create video adapts the mechanism into a new situation and never remakes a reference's scene.
- **Transfer, not repetition (Create).** Every reference has two layers. The craft layer is collected and reused freely, as kinds rather than instances: the style (look, palette and grade, lens and framing habits, light, era, performance register, stylised or real), the properties (length, pacing curve, cut rhythm, first-cut and speech-onset timing, caption grammar and text role, sound role, camera behaviour), the approach (format name, hook type rather than the hook, structure shape, escalation and reveal logic, payoff timing, interaction pattern, laugh mechanism, emotion arc, loop logic, how the viewer is addressed), the crafting (one take or cuts, POV or observed, where the text sits and when, when and how the product reads, how the ending is built) and why it works. The subject layer is left behind: the premise and situation, the setting, the characters and their look, the action sequence, the joke's content and punchline, the lines, the caption wording (a generic meme line excepted), the props and their arrangement, the first-frame composition, the ending image, the source product's own beat and the sound (a cut meme insert excepted). The analysis card keeps the two apart, and the synthesis writes a craft sheet per family with a "collected" and a "left behind" column; ideation reads only the collected column, takes its subjects from the audience model and the product's natural use, and never takes a subject line from a card. Every seed, the sharpness gate and the creative check run the copy test: would someone who has seen the reference recognise the same premise, setting, character type doing the same action, turn, lines or sound, first frame, ending image, or the product doing what the source product did at the same beat? One yes makes the seed a remake: it is rewritten with a new subject or dropped. The test runs against every reference of the family and between the run's own videos. A format whose identity is its fixed frame keeps that frame as a property; its content still changes.
- **Ideation, scored.** For every Create video slot, at least five concept seeds (situation + turn + where the product lives), each scored on stop power, relatability, sharpness, product nativeness, trend fit and freshness, feasibility for the locked model, and brand safety; the best wins, the runner-up is kept as the fallback, the winner's share line and job are written, and no two videos of a run share a situation, a turn or a product beat. The picks are shown one line each with the reason; the user may swap them by replying.
- **Sharpness gate.** A concept enters a plan only if the idea fits one sentence and reads from the clip alone, the first second shows something rather than a setup, there is a real turn and a payoff on the family's beat, a specific viewer would send it, the product's presence is explainable in one clause, the clip loops or ends strong, and nothing in it is generic (a "person enjoys product" beat, an explained joke, a stock situation, a dated meme).
- **Recreate.** The ranking adds each reference's creative potential: mechanism strength, fit to the goal and the audience, how natural the product's integration can be, the freshness of its surface elements, and the risk of reading as a copy.
- **Brief and QC.** Every brief says why the video will work (goal and job, the one idea, the emotion arc or laugh mechanism, the share line). After the physics and continuity checks, QC judges the clean video as a viewer: the hook within the first second, the payoff where planned, the product recognisable at the moments of attention without reading as an ad, the planned arc, the loop. A missing hook or payoff the plan required is a narrative failure and a regenerate reason; everything else is a note, never a question.
- **Precedence.** The creative layer never overrides physical and logical correctness, the must-not-survive list, the permission rule, the house text style, the product rules or the user's instructions and house approach; it decides what wins inside them.

The main purpose of Analyze Mode is not merely to describe content. Most source material will have been deliberately collected because it appears useful, successful, viral, engaging, high-performing, or structurally valuable. Compare references and infer the recurring mechanisms that make the content effective. Analyze hooks, first-second behavior, curiosity, relatability, humor, demonstrations, storytelling, educational value, spectacle, transformations, POV framing, visual interruption, editing rhythm, pacing, camera behavior, shot composition, user interaction, emotional response, loopability, retention, payoff timing, comments, sharing potential, audience targeting, content structure, and any other relevant characteristics surfaced by the material.

Do not force the analysis into a fixed set of content categories. Dynamically infer styles and patterns from the source files. Content may be organic footage, UGC, tutorials, memes, educational content, animation, product demonstration, talking heads, POV content, reactions, cinematic content, screen recordings, software demonstrations, finance content, social commentary, storytelling, hybrid formats, or completely different structures. Create categories according to the actual material.

Group references according to both their execution style and what they are actually doing or communicating. Extract content families dynamically from the dataset. Determine typical length, pacing, hook timing, shot duration, payoff timing, camera style, editing logic, content structure, and other useful recurring patterns for each discovered family.

Before generation begins, understand the assets the user supplied at the start and build a reusable project-level asset registry from them alone:
- Group the supplied files into entities. Each distinct product, object, character, mascot, interface, brand kit, environment or sound is one entity. Multiple products, samples, variants and characters are expected, and sub-folders usually separate them, but verify by looking at the files.
- Record the other views, the variants, the real dimensions and the usage notes found in supplied documents.
- Write every product's or object's affordance sheet (see "Counts, openings and object permanence" below): its parts, openings, opening sequence, how it is used and held and by whom, the contact point, what it holds and how many and whether that shows, its states, its real size by comparison, the orientation of its mark, and what it cannot do. Where an image does not show a part, say so and keep the use to what is known. In Edit Mode, write it for the replacement product whenever the edit has it handled or used on screen.
- Ask one consolidated question only when a genuinely consequential ambiguity cannot be resolved by looking at the files. Otherwise proceed autonomously.
- When a concept needs something the user did not supply, adapt the concept to the supplied assets. Ask only when no adaptation preserves the content mechanism.
- Never fill a gap with material from the reference folder.

When physical products or objects are involved and accurate geometry matters, identify the canonical template or source-of-truth reference among the supplied files: the cleanest, most complete geometry view, or the file the user marked as the template. Treat it as the authoritative reference for size, proportions, shape, curves, silhouette, physical construction, packaging structure, and other stable characteristics. Treat the other supplied variants as appearance changes that must not unintentionally redefine the fundamental geometry unless explicitly specified.

When characters or people are involved in Analyze Mode, use the approved character references supplied at the start rather than asking for them before every generation. Preserve identity and use the supplied characters as replacements when the reference video's original person should not be retained. If several approved characters exist and there is no explicit assignment, vary them intelligently across generated videos instead of always using the same one. Likewise, fit each supplied brand to the scene first (a food, grill, party or sport scene suits a drink; a desk, class, meeting, work or commute scene suits a focus product; the plan states the tie in one line, and a reference with no tie for one brand goes to the other), then pick the form that fits the scene's scale and register (the smallest closed form in a casual handheld scene, a large pack only where a large pack belongs; the forms keep their real size ladder, a pouch larger than a carton and a carton larger than a sachet, a retry changes the anchor or the posture of the same form, and a smaller form is never put in for a planned one because the client reads it as a different product) and then distribute several supplied products or variants sensibly across videos unless instructed otherwise.

When another entity in the reference video should be replaced by the client's entity, perform that substitution with maximum practical fidelity. The concept applies dynamically across industries. A physical product may replace another physical product, a character may replace another person, an app interface may replace another interface, a brand may replace another brand, a digital asset may replace another digital asset, or some completely different analogous substitution may be appropriate. Infer this from context rather than hardcoding specific brands, industries, or object types.

Generated content should preserve the useful structure, behavior, actions, pacing, mechanics, cinematic logic, or engagement mechanism of the reference while adapting the identity-specific elements to the current client and project. Do not unnecessarily preserve competitor branding, source identities, unrelated logos, usernames, watermarks, or other reference-specific artifacts.

What must not remain, and what is fine (all modes):
- **Must not remain:**
  - the original person or character being replaced;
  - the original product being swapped, and any competitor product of the client's category;
  - overlay text, subtitles, captions, stickers, usernames and handles;
  - TikTok, Instagram, YouTube Shorts, CapCut or any other platform logo or watermark;
  - featured third-party branding: a readable brand name or logo that is held, used, centered or in close-up;
  - a copyrighted character as the subject, and studio, film or character names in prompts;
  - what the generation service refuses to render (moderated requests, detected intellectual property, a model's own real-face refusal): sexual content and nudity, graphic self-harm, hate symbols. This is a block, not a rule: the job fails, so the plan avoids it, a reference built on it is dismissed, and a brand rule cannot enable it.
  That list is the copyright and ownership floor plus the service blocks, and it is the whole of the pipeline's own defaults. The pipeline has no content rules of its own: weapons, alcohol, tobacco and vapes, gambling, drugs, gore and fake blood, dangerous stunts, profanity, political or religious content, the faces in meme inserts, celebrity cameos and anything else a brand might dislike stay exactly as the reference shows them unless the client's guardrails name them, and nothing is ever blurred, pixelated, softened or removed on the pipeline's initiative. The brand's documents add content rules; they never remove the floor.
- **Fine, never flagged:** UGC is full of everyday branded things. Background decor such as posters, plushies, ornaments and toys (even a Kirby poster or a Hello Kitty ornament), clothing and footwear logos (an AYBL hoodie, three stripes), shop and street signs, brands seen in passing, meme inserts with their faces as cut from the reference, and all brand-dependent content that no guardrail names are normal. They are never flagged, never asked about, never softened, and never cost a retry.
- **Fixes:**
  - Small static leftovers, such as a watermark, are removed locally for free.
  - Anything else on the must-not-remain list gets one corrected regeneration; if it still fails, it is reported at the end.
  - In Analyze Mode, quality-control findings never become questions to the user.

In Analyze Mode, some reference videos will contain nothing related to the client's product. For example, the client sells a canned drink, a chewing gum or a car, but a reference shows a person telling a funny story with nothing to drink or chew, a man crossing a street with free hands, or a sidewalk interview with no car in shot. Such videos are still valuable for their content mechanism and must be analyzed like any other. During analysis, record for every reference video the most suitable way for the client's product to be part of it:
- **Swap:** the reference shows the product's analog in the same form, such as another can for a canned drink, another gum pack for a gum, or another car for a car, and it is replaced.
- **Contents:** the reference shows the product's category in another form or vessel, whatever its role in the story, such as a glass of water on the subject's table, a drink in a cup, or gum pellets shaken into a palm.
- **Placement:** nothing analogous exists.
For contents and placement, also record the placement opportunities: when the character's hands are free or busy, which surfaces are near the subject and in which shots they are visible, where a large product would naturally stand (the curb, a driveway, a corner of the room), and how the light falls on those spots. A source object that is not analogous to the client's product must never be forced into a swap; a phone is never turned into a can, and a bicycle is never turned into a car.

When the client has a product, a physical object, or software that can appear on a device screen, every Analyze Mode video must show it, unless the user or a document says otherwise. The system identifies the most suitable use and blend of the product in each video. The reference's story, hook, beats, dialogue, timing and payoff stay untouched; the product adds nothing to them and takes nothing away. The product is used the way it is really used (a drink held or sipped, gum unwrapped and chewed, a cream applied, a phone used, a car driven, parked or leaned on) only when the action has room for it; otherwise it is simply present. Whatever the product is, its size, weight, states and motion stay logically and physically correct for that object.

The contents form keeps the reference's vessel or form and its action, and turns what is inside into the client's product. It applies whenever the video shows the product's category in another form or vessel, whatever its role in the story, including vessels the plan adds and props that come from a supplied photo. For example, a man at a café table with a glass gets a glass of the client's orange sparkling drink, in the flavor's color and texture, with the open can beside it; a glass of water next to the can is wrong. The switch is skipped only when it would be illogical: the joke depends on that exact drink, the serving contradicts the product (a steaming coffee for a cold drink), or the glass belongs to a background stranger. Ice may stay; a garnish that clashes with the flavor becomes the variant's fruit or goes. The drink comes from the package, so the package is open and the amounts add up. Contents samples are often among the supplied files without a label, so the system looks for them in every supplied image. Example: a reference captioned "first day as an assassin" shows a man pouring a strange white powder into a cup of drink, stirring it with his finger, forgetting, drinking it himself and dying.
- The new video shows the same gag.
- An open can of the client's drink stands beside the plastic cup.
- The cup is filled with that flavor's liquid, matched to the liquid texture sample supplied with the assets.
- The ledger keeps it logical: the cup's level matches what the can could have filled and drops only when he drinks, and the can stays open and in place.
- Without a contents sample for the chosen flavor, use a flavor that has one, or fall back to placement and say so.
The same form works for other products. Someone who pops a piece of gum mid-story takes it from the client's open pack on the table, and the pack then holds one piece fewer. Amounts always stay consistent with the package and change only through a visible action.

For a placement video, the system must find the most suitable place in the scene and integrate the product as if it had always been part of the original footage. The anchor depends on the product's size and use. For a handheld product (a can, a gum pack, a cosmetic, a phone), choose where it sits with this order of preference:
1. In the character's hand, when a hand is free or moving casually (talking, gesturing, walking, sitting relaxed) and holding the product is natural to the activity. One hand holds it, the same hand throughout, while the other hand makes the gestures the reference needs. Example: a man crossing a street does a one-second "respectful jog" to thank the driver who let him pass. He holds the can, or the gum pack, the whole way, through the jog and back to walking. An item in a gesturing hand moves less and is held the way it naturally would be: an open drink stays upright, an open pack does not spill its pieces.
2. Otherwise, standing on a surface the character plausibly owns, within reach: a desk, table, counter, nightstand, shelf, sofa arm or cup holder.
3. Otherwise, somewhere else in the environment where such an item naturally lives.
A large product (a car, a motorbike, furniture, an appliance) stands where such things really are: a car parked at the curb, in a driveway or passing behind the action; a chair or a fridge in the room. It is used only when the action invites it (getting in, leaning on it, driving off), and it obeys its own physics. Software appears on a phone, laptop or monitor in the scene, showing the client's real interface.
If none of these is logical, add the smallest element native to the setting (a side table at the frame edge, a car parked across the street) and state it in the brief. Never let the product float, appear out of context, or sit somewhere it could not really be.

The size reckoning. A can once stood on a bedroom dresser behind the subject at two to three times its real size, taller than the water bottle beside it. The product's size in the frame is therefore reckoned, never guessed, for every product in every shot. The asset registry records each product's real dimensions (height, width or diameter, depth, in centimetres, and the volume) from the supplied specs, or the category's standard size marked as inferred when no spec exists; a size is never read off the product's own photo, because a packshot fills its frame. The plan then writes, per product and shot: its distance from the camera, derived from the frame and never assumed (in Recreate from the source frame: the surface the product stands on, a same-plane neighbour of known size, the depth order; in Create from the blocking the plan asks for; the shot-size distances are priors for a sketch, never for a verdict), with the basis written beside the number (a product on a dresser behind the subject is farther than the subject); the lens the look implies; the expected fraction of the frame height, from the rule that a 9:16 frame covers about thirty-six times the distance divided by the 35 mm-equivalent focal length, so a 15.7 cm can at 2.5 m through a 26 mm lens fills about one twentieth of the frame height; the one named neighbour of known size at the same depth and the ratio to it in words; the size ladder between the run's products when more than one shows; and the size the product keeps across motion, exits and cuts. The toolkit computes the expected fraction and pixel height for any distance and lens, and a table over the usual shot distances. The prompt carries the reckoning in the model's phrasing (the ratio to the neighbour, the depth, "a small object in the background" where it is one, the ladder, a constancy line), the product reference is padded so the product does not fill its image, and, for a model that takes a start frame, a frame is built at the reckoned pixel height and measured before it is animated; on a model whose guide lists size as a model limit (Wan 3.0 Prime, where the sizing words, fractions, neighbour ratios, padded references and exclusions did not move a small placed product in twelve of twelve comparable retries, a limit established for small flat packs against a same-plane neighbour and unproven for cans (their measurements used an assumed distance or a head at another depth; pinning the product to a neighbour at its own depth is the lever still to test), and where a start frame cannot be combined with the source video) these are a check, not a control. The control is a size-and-place guide: an extra image reference that shows only where the product stands and how big it is beside a neighbour, in the scene's own perspective, built locally from the source's bare surface scrubbed of the performer, skin, clothing, lettering and captions in Recreate and Edit Mode, or from neutral texture in Create (never from an unscrubbed source frame, which brings back the replaced person, the sponsor lettering of a jersey and the lettering of a screen, and is then copied as a flat sticker) with the product shaded and turned like the scene, a soft contact shadow, a sharp label and a thin edge, bound in the prompt as spot and size only ("exactly where Image 4 shows it ... keeps exactly the size it has in Image 4"), the relation to the named neighbour stated once and no fractions of the frame, padded-reference phrases or "no oversized" exclusions relied on, and put into the first request whenever no passing-list anchor fits and always for a near-plane spot the user marked; eight guided takes landed within 1.25 times where wording had never moved the size, and the guides that failed failed on place or on copying, not on size. Otherwise the plan chooses the anchor class from the guide's passing list: in the hand that holds it or swapped for the source's own handheld object, or, only when the planned package is the flat sachet, lying flat on a bare near-side surface; a bare surface beside a large rigid object of the source in the same plane, or any near-plane spot, is not on the list, needs a guide as well and holds only where the spot checks below hold. Quality control measures the product's pixel height against the named neighbour's at the product's own depth (the depth ratio read from the frame when the product stands in front of or behind it, never assumed to be 1) on a full-resolution frame at rest, one in use and the last, runs the toolkit's comparison (observed against expected, by neighbour ratio and by distance and lens), which needs two independent estimates that agree (the neighbour ratio, and the frame fraction at a distance derived from the surface or another object) before an oversize verdict, while a verdict from one assumed number is provisional, printed as such by the toolkit, never a regenerate reason or a flagged failure, and viewed on the full-resolution frame by whoever reports it (agent or main session) before it is flagged, repeated or summarised; when the user's eye disagrees it is re-measured, not defended (a can under a metre from the lens was once reported at 2.8 times its size from an assumed distance of 1.5 m and was 1.07 times by eye); it writes the observed multiple of the expected size in the verdict and compares across cuts. Within fifteen percent is accepted; fifteen to twenty-five percent is a note only for a static product with a readable label; more than that, a size that changes between shots, or a product larger than the hand that holds it is a regenerate reason with no post-fix, because nothing in post can shrink a product inside its scene. On a model with a listed size limit the retry changes the lever (the guide, the integration form or the anchor class), never the sizing words; a second miss ships the best take flagged, with both attempts written as blocks in the brief. A stylised video keeps the same ratios: an anime can is still one hand tall. The standard-size table (hands, faces, bodies, cans, bottles, phones, furniture heights, doors, cars) lives in the anomaly catalog as the comparators for the reckoning.

The placed product must be noticed, not featured. It must not be the focus of the video, and it must not be ignored or hidden either. It appears at real scale, off-center, in the mid-ground near the subject (a large product where it naturally stands, never blocking the action), and it is visible for most of the video. Its brand mark (label, logo, badge or screen) is turned roughly toward the camera so it is recognizable at a glance, but it is not posed like a packshot. It gets no light of its own, no push-in, no cutaway or insert shot, no one presenting it to the camera, and no mention in dialogue or captions unless the user asks for it.

The placed product has exactly one location at any moment, and it keeps that location for the whole video, through every cut, angle change, reframe and camera move. It must never stand on the desk in one moment and on the table or a chair a few seconds later, and a parked car never moves along the street. It may move only through a visible, logical action, such as the character picking it up to use it and setting it down again, moving it out of the way, handing it to someone, or taking it when leaving; a vehicle is driven or pushed, never slid. Such interactions are rare (one or two at most), happen at natural pauses rather than on the hook or the key beat, keep coherent states, and are tracked in the entity state ledger like any other state change. A product that gets used is ready for that use from the start or made ready on screen (a can that is drunk from is open; a car that drives off has its driver get in first), and a changed state stays changed (a pack missing a piece stays missing it; a car's lights, engine and doors keep their state until someone changes them). There is only ever one instance of the product. It is in frame from the first frame wherever its anchor is in frame (a product absent in the opening seconds that then appears is a regenerate reason, never a flagged note), on a fixed natural surface that the source frame shows, and its position is read against a fixed neighbour at least every 0.25 s across the clip and every cut; a cut alone is not a motive for a move (it shows another angle of the same spot, or the cause is on screen), and a product that drifts with no action is a regenerate reason. The spot is read off the source's first frame and checked before it is chosen: bare at frame 0, in frame along the whole camera path (a near-side spot beside a lid leaves the frame when an orbit passes over it), outside every hand's lane in every beat (resting, writing, page-turning and pick-up sweeps included, with the object a hand picks up named so it cannot turn into the product), wider than the product and not cluttered, not the nearest plane of a table-level shot (it renders hero-sized; a near-plane spot the user marked stays, with a guide), not "in front of" a lid, keyboard or mouse that the model would put it on, and fully inside the frame (a product cut by the frame edge pulled the camera into a push-in and cost the performer's pose); a spot the user marks is the anchor, and a reference with no spot that passes ranks low for a placed product.

Posture, support and place. A placed or carried product takes the posture its shape allows (a flat sachet or pouch lies flat, label up; a small flat carton lies flat on a bare surface, the way people leave it, and stands only for a reason the plan states; a stand-up pouch laid flat needs a reference that shows it lying flat in perspective; a can stands on its base), rests on something that is visibly in the frame (a fixed bare surface the source shows, such as a counter, a desk or a grill's side shelf, or a large solid object it already shows; never a prop that moves or is carried away, such as a cutting board), and sits where a person would really leave it, out of the way of a working hand or arm and never touching the person, with its story reason in one clause in the ledger row. Nothing leans on a prop the model has to invent, nothing stands on its edge against a person, nothing rests on or overlaps a thin sheet that hands move or write on, and a placed product never takes over a pick-up, use or hand-off that belongs to another object: the prompt names the object that is picked up and says the product stays. The prompt writes posture, support and reason as one positive sentence with its exclusion; quality control checks posture, support, clearance and the sheet region at 30 fps on every rest and every pass of a hand or sheet, and writes the story reason as its own line of the verdict; a break regenerates with no post-fix. A small flat pack is left casually, at one side, partly tucked beside a neighbour, never upright and fully displayed at the edge; its state follows the scene's use (a snack or gum pack at a class or desk scene is open, a drink at a table is cracked), decided in the plan and written as one positive sentence with its exclusions.

Preparing the source and writing the request. What must not survive is changed in the prepared copy, not only in the prompt: a front-camera selfie shown un-flipped (reversed shirt print, a left-handed guitar) is flipped before upload in Recreate (in Edit Mode only when the user asks, since only the planned operations change), and a mirrored identity photo with it, with the action script's sides swapped and the prompt saying that the video is already in true orientation; no tool ever removes a caption, a name or a patch from a source in Analyze Mode (no inpaint, delogo or crop): the clean-plate lines (do not inherit text, captions, usernames or watermarks; no subtitles; no on-screen text anywhere) are the highest-priority lines of the prompt and are never trimmed, the character swap is pushed in the script, and a real person's name or a patch on the kept garment is written as an edit of the source surface; a face effect baked into the reference (a mask, a filter, a clone) is planned for up front or accepted flagged; a reference with many hard cuts or one that alternates a person with person-free close-ups is generated as separate clips on its own cuts. Quality control lists the output's cuts beside the source's shot list (the same count at the same times, person-free cutaways still person-free, the placed product in every shot where its anchor is in frame, the closing emotion beat present), and a merged, dropped or dissolved shot regenerates. A swap is a replacement ("replace only the cup with the can at that exact spot, on the same footprint; the cup does not remain"), anchored by the neighbours that border the source object, and a source object a guardrail names is removed with a named replacement. A camera lock is its own sentence when the product sits near a frame edge or the shot is handheld or an orbit; an empty surface is written empty, per shot; the one hand in frame is named with the bare empty area; the identity image is cropped to the face when its clothing differs from the kept garment, which is named in positive words, and a cut-off print is cropped away; the clean-plate lines are never cut to fit the length limit. A label that must read is a pixel budget: a wordmark needs about 25 px of upright height and a variant tag (flavour, size or model) or badge about three times that, the plan writes the limit in the brief before generating, quality control reads the label word by word on a full-resolution frame, and a wrong letter regenerates (upscaling is no fix). A hand that covers, wraps or passes through the placed product, a product that leaves the frame along the camera path, or the performer's pose lost in the last third regenerates.

The placed product must merge with the ambience of the video, so that it never looks like an edit:
- It takes the scene's lighting direction, softness, color temperature and exposure, with highlights and reflections that match the actual environment; a car's paint and windows mirror the street.
- It casts a contact shadow consistent with the other objects, sits on its surface without floating or intersecting it, and matches the camera's perspective; a car's tyres sit on the ground with dark contact patches.
- It shares the footage's depth of field, grain, motion blur, color grade and white balance.
- It sits in a lived-in, slightly angled pose.
- It shows no halo, cut-out edge or sharpness mismatch.
- **The paste test.** A can once stood on a bedroom dresser two to three times its real size, squared to the lens like a packshot, lit flat and cool while the room was warm and dim, sharper than the plate, with no contact shadow and drawn straight-on while the camera looked up at the dresser. "Looks pasted in" is therefore measured, never felt, through eleven signs checked on one full-resolution frame at rest and one during any interaction, against the nearest neighbour at the same depth: whites brighter or cooler than the nearest white object; flat front light in a room lit from elsewhere; no contact shadow or one falling another way; crisper or cleaner than objects at the same depth; a packshot pose; ellipses and verticals that do not match the camera height; a size that disagrees with the neighbours; hard, haloed or cut-out edges without reflection or colour spill; a footprint on the very edge, overlapping a neighbour or floating; the wrong depth of field; being the brightest, most saturated or most centred thing in the frame. Any sign regenerates, and the retry fixes the named cause: the product reference is scoped to shape, proportions, colours and label ("do not use its lighting, exposure, background, shadow or camera angle"), the prompt states the room's light on the product, its size against a named neighbour, its mark angle, its contact shadow like the neighbour's and the scene's camera angle, tight crops are padded, a start frame passes the test before it is animated, and the anchor is chosen to force integration: touching or partly behind another object, inside the lamp's falloff, never alone on an empty edge. The prompt also names the product's material (a curved metal body with a soft highlight, a faint reflection of the room, the label wrapped around the curve, shading darker toward one side, a soft contact shadow, not a flat cut-out); the grounding lives in a close-up reference of the object on the scene's real surface bound as the look and grounding reference, with one packshot kept for the printed label only; the base is cropped at 3x and compared with a same-scene neighbour; and a paste sign is never written down as a note. The only post-fix is a local regrade of a static, untouched product that fails on exposure alone.
When writing the generation prompt, describe the product as part of the scene from the first frame, at its anchor, rather than as something added. Avoid edit verbs and advertising vocabulary, state that it stays in place and pin its spot to a fixed neighbour, restated for every shot and across every cut, and exclude duplicates. State what every glass, cup or other vessel holds, from the contents sample, because a vessel whose contents are not stated comes back as water. When a character or environment photo shows props such as a glass, a cup or a snack, plan them as the product's contents or limit that image's role to the person or place, so nothing carries over by accident. When a reference video drives the motion, state that the product belongs to the new scene even though the reference has none, keep the reference's actions, and, if the product is held, name the hand that holds it while the other hand performs the referenced gestures. The product keeps its real printed label, logo or badge exactly as in its reference images: clean-plate wording must carve it out instead of banning all logos, and quality control treats its words as allowed text. After generation, check that it is present, recognizable, in one persistent location, and matched to the plate. Regenerate when it is missing, duplicated, jumps between locations, is featured like an advertisement, or looks composited, and when a glass or other vessel of the product's category holds something else, such as water beside the can.

Text handling must depend on the active mode.

In Edit Mode, visible text from the source video must not remain in the resulting video unless the user explicitly requests that specific text to be preserved. This includes captions, subtitles, usernames, watermarks, title cards, meme text, stickers, social-media overlays, interface elements, timestamps, logos used as overlays, random lettering, and other baked-in textual elements. In Analyze Mode, every video is generated without overlay text, as a clean plate. All overlay text, such as a "POV: …" line, a "when …" line, a hook or a caption, is placed afterwards as CapCut text layers over the video, at the position and timing of the reference's text.
- **House text style.** Every CapCut text layer, in every video, uses the font System, size 10, and the user's chosen CapCut preset (white text with a black outline). CapCut keeps its preset tiles on its servers rather than in a readable file, so the pipeline learned the exact preset once from a text the user styled in their project 03_Oct_2026_v09 and locked it in its configuration; the repair step applies it to every text layer after every save. Every text layer is also horizontally centred: only its height (top, middle or bottom) follows the reference, and when centred text would cover the product, a face or an insert it moves up or down, never sideways. The reference's look never changes the font, size, color or preset, supplied brand fonts are not used for overlay text unless the user asks for them, and the preset is never re-learned or replaced unless the user explicitly asks for a different one.
- **Wording.** In Recreate, the reference's overlay text is placed back word for word. In Create, a generic meme line that carries the joke may keep its wording, while anything source-specific is rewritten for the client and concept. Usernames, handles, watermarks and source brand names are never copied. A guardrail rewrite is minimal: only the banned element (a number, a statistic, a name) is removed and the same thing is said in the same grammar, keeping the reference's subject and meaning, never an unrelated line. A reference's short keyword or tag that is its hook, or any text the user keeps, is placed word for word. A source overlay that carries the joke's context (a notification, a message, a banner) is the original element, cut from the reference's own frames and placed as a picture overlay on exactly its visible frames and faded with the picture under it, never re-typed as text. No text layer contains an emoji (strict).
- **Quality.** Text must stay intentional, readable, contextually correct and consistent: no pseudo-text, malformed letters, words that change between frames, duplicate captions or stray lettering.
- **Lettering in the generation.** The only lettering the video model renders is the product's own printed label, logo or badge.

Some references interrupt their own footage with an insert: a meme clip, a film or TV snippet, or a reaction image, usually with its own sound. For example, a 27-second video has 13 seconds of footage, a 2-second meme with a meme sound, and 12 more seconds of footage.
- **Only the reference's own content is generated or edited:** 25 seconds here, with a natural beat boundary where the meme goes.
- **The meme is cut from the original reference with its sound.** A video meme is always cut, never reduced to a screenshot; a still image meme may be a screenshot with its sound under it. Overlays the reference added on top of the meme are removed.
- **Cut on frames that hold only the insert, and keep the timeline whole.** An insert's in and out are moved past any dissolve, flash or frame of the replaced performer, so the final never shows the person who was swapped. In Recreate the reference's timeline and its original audio stay whole and unspliced: the edge span stays as pure transition colour of the same duration, the neighbouring piece fades into and out of it on real moving footage, and a held or frozen frame is never used under a transition. Overlays exist only on their visible frames and fade with the picture under them.
- **The 30-second rule counts only generated content.**

Every Analyze Mode video ends as its own CapCut project, named with the date and the video number, for example "01_Oct_2026_v03", created and edited through the CapCut MCP.
- **The edit:** the clean video is placed, split at each insert point, and each insert goes in its gap. In the example: place the 25-second generation, split it at 13 seconds, place the 2-second meme, and continue with the other 12 seconds. The same logic holds for longer or shorter videos. Every overlay text is added as a text layer.
- **After saving:** the project is registered, the house text style is applied to every text layer, its timeline is synchronized and linted, and a low-resolution preview is rendered for review.
- **CapCut must be closed while a project is written.** If it is open, the run continues, and the projects are written at the end after asking the user once to close it. The final export happens in CapCut.
- **Deliverables:** every video of the run has its clean and preview files in the run's one deliverables folder with a row in its README (a with-inserts clean is built from the pieces, the inserts and the original audio and is never overwritten by a generated-only clip), and the wrap-up verifies it, together with a scan that no text layer holds an emoji.

How multi-generation videos are built on Higgsfield, based on official provider and Higgsfield documentation:
- **Fill one generation first.** Seedance 2.5 and Wan 3.0 Prime reach 30 seconds. Put seams on the reference's own cuts, where they are invisible.
- **Continue a single continuous take only where no cut exists:**
  - Seedance 2.5 has native forward extension. The accepted clip (2–30 seconds, passed by job id) is extended; the result is only the new part, and its repeated first frame is dropped at the join. At most two extension hops per take.
  - FLUX 3 Video continues a supplied clip through its video reference, with a new segment of up to 15 seconds.
  - Models with start and end frames use a keyframe ladder.
  - Models with only a start frame chain the exact last frame of the accepted clip, extracted losslessly, as the next start image.
  - Models without a start-frame role join only on cuts.
- **Seam discipline:**
  - Every clip passes quality control before the next one is chained from it.
  - Each seam has a written hand-off state, restated in the next clip's prompt.
  - Every clip uses the same references and wording; speech never crosses a seam; chains stay short, at about three hops.
  - A jumpy join is fixed in this order: trim six frames from the end of the earlier clip and one from the start of the later; else bridge it with a first-and-last-frame transition; else move it onto a cut.
- **Where it is recorded:** each model's maximum per generation and its join method are in the model index, and each model guide states its continuation wording.

Evaluate physical size, dimensions, scale, proportions, silhouette, shape, curves, geometry, orientation, perspective, depth, camera distance, camera angle, location in the frame, relation to the character, relation to surrounding objects, supporting surfaces, foreground and background elements, contact points, hand placement, grip, occlusion, motion, apparent weight, gravity, inertia, material properties, reflections, highlights, shadows, lighting direction, lighting intensity, light temperature, exposure, environmental illumination, and any other physical or visual relationship necessary for believable integration.

The supplied canonical template or source-of-truth reference must remain authoritative for the identity and geometry of a client asset. Every replacement must also make contextual and logical sense. Determine why the object or entity is there, how it arrived there, what the character is doing with it, where it previously was, where it moves next, how it is being held or interacted with, and what state it should have at every important point. Do not optimize one attractive frame while creating contradictions elsewhere in the video.

Treat the entire video as one continuous evolving state. Track important characters, products, objects, containers, liquids, interfaces, environments, clothing, props, and other relevant entities from the first frame to the last. Earlier actions must constrain later actions. If an object is placed somewhere, it must remain there until something visibly moves it. If a container is opened, later moments must reflect that state. If liquid is poured, its amount and destination must remain logically consistent. If a piece is taken from a pack, the pack holds one fewer. If a vehicle is parked, it stays parked until someone drives it away. If a character picks something up with one hand, it must not inexplicably teleport into another hand. Camera changes must preserve the spatial arrangement of the scene.

The agents must evaluate physical logic, spatial logic, temporal logic, narrative logic, environmental consistency, asset fidelity, camera continuity, lighting continuity, motion continuity, interaction realism, composition, pacing, transitions, and the relationship between all of these factors before execution.

Human and object interactions must remain physically believable. Avoid malformed hands, impossible grips, fingers passing through objects, floating products, unsupported objects, intersecting geometry, incorrect body mechanics, unnatural movement paths, inconsistent apparent weight, broken pouring behavior, liquids appearing or disappearing without cause, containers changing state incorrectly, vehicles sliding or wheels that do not turn with the motion, or similar physical anomalies.

Every moving thing must obey momentum, friction, gravity and contact, whatever the product or scenario. A spun object slows down and wobbles. A tossed or flipped object (a gum pack, a coin, keys) rises, arcs, tumbles at a steady rate, falls, and lands on whichever face its spin brings down. A vehicle accelerates and brakes gradually, pitches under braking, rolls in a turn, turns its wheels at the speed it travels, never slides sideways without a cause, and swings its doors on their hinges. Liquids, powders and pieces fall in an arc, fill, spill and are conserved. People shift their weight and react to what they touch. Motion that has to end in a specific state is a common place for models to cheat: a spinning can that must land logo-forward, a toss that must land face-up, a car that must stop on an exact mark.
- **What the cheats look like:** the object snaps to a new position or angle in a single frame, stops on the pose and then resumes without any new push, reverses, slides without a cause, or its label, badge or body morphs.
- **How to prompt it:**
  - Describe such motion by its physics (the cause, such as a flick, a toss or a push on the pedal; the direction; how it speeds up or slows down; roughly how far or how many turns; the end state), never by a schedule of exact times.
  - Give a required end state a visible cause: a hand stops the spinning item or turns it label-forward, the character catches the toss, or the driver brakes and steers into the spot.
  - Time any text that plays on the product, such as a logo pun, to the moment the product really shows it in the generated video.
- **Quality control** checks every motion beat at the full frame rate and regenerates on any snap, pause-and-resume, reversal, slide without a cause, or morph.
- **Retries:** a corrected regeneration removes timing constraints from free motion; it never adds them.
- **In Recreate:** when a reference's payoff depends on its own object's geometry, such as its logo landing between two caption words, or its size or wheelbase, the client's product is different. Keep the reference's beat, but not its exact timing for that motion; the analysis notes such payoffs on the reference's card.

Counts, openings and object permanence (the anomaly catalog). Two anime Create videos showed what a ledger that only tracks where the product is lets through: three capsules on a desk became one after the character walked past them and came back, and a boy drank from the side of a flip-top straw bottle that has no opening there, after his mother had filled it with milk. The pipeline therefore keeps a catalog of such logical and physical anomalies, general for every product, with the prompting and quality-control steps stacked against each class. The examples only illustrate the classes.
- **Affordance sheet.** For every supplied product or object, the asset registry records, from the images and specs: its parts; its openings (where the contents come out and where they go in); the opening sequence (the visible steps before any use: flip the cap up, lift the tab, tear the notch, unscrew the lid); how it is really used and held and by whom (through the spout with the head level, because it is a straw; tilted to the mouth with the head back a little, for a can; with both hands, for a child); the contact point (lips on the spout, the thumb under the tab, a pump pressed with one hand into the other palm); what it holds and how many and whether that shows (a frosted bottle shows its level, a can never does); its states and which are irreversible; its real size by comparison (a hand's length); the orientation of its mark; and what it cannot do (drinking from the lid's closed side or through the body, a strap on the base, a visible level in a can). The sheet is the authority for how the product may be handled: the plan quotes it in the ledger, the prompt quotes it in the use beats, and quality control checks against it. The same sheet is written for gum cartons, pouches and blisters, capsule bottles, tubes, pumps and sprays, cartons, straw cups, earbuds, phones and laptops, cars, fridges, bags and chairs.
- **Classes.** Counts and conservation (every multiple is counted at the start; the count changes only through a visible cause, by the amount it explains, and what was taken exists somewhere: a pack of ten holds nine after a piece, a full glass from one can leaves the can nearly empty, a bite leaves a bite mark). Openings and use (every use goes through the part built for it, after the step that readies it, with a real contact point: never a can sipped through its side or a sealed top, a bottle drunk through its closed cap, a blister pressed from the front, a tube squeezed from its cap, a phone used with its back to the user, a driver entering by the passenger door). Preparation and causality (cause before effect: the glass fills only after the pour, the jaw chews only after the piece is in, the face reacts only after the sip; a can that is cracked on screen is sealed at frame 0, so no reference image may show a later state than the first frame). Irreversible and persistent states (opened, torn, bitten, poured, spilled, wet, lit and written stay so; a lid, door or switch keeps the state it was left in; levels move one way between causes). Object permanence (what leaves the frame, passes behind a hand or sits across a cut comes back with the same count, spot, state and size; reflections and shadows agree). Liquids and materials (level surfaces, pours in an arc from the opening, conservation, milk opaque white and a sparkling drink clear with bubbles, a cold drink sweats and a hot one steams, ice floats, cream absorbs over seconds, powder dissolves when stirred). Scale and proportion against hands, faces and furniture in every shot. Body mechanics at the product (head back for a can, level for a straw; lips closed around the spout; nobody speaks clearly with a full mouth; fingers wrap the real shape and never pass through it; no second copy in the other hand). Orientation, label and parts (they belong to the body: never mirrored, never rotating on their own, never migrating; a strap stays on its loop; the flavor and variant stay the same). Ownership and hand-offs (after a hand-off the giver's hands are empty and the receiver holds it in the state it was given). Environment, context and suitability (a car on a road with its wheels on the ground, entered by the driver's door; a fridge door on its hinge; the window light keeps its direction; dropped things fall; a kid stays a kid with kid-sized things, and no energy drink or supplement goes to a child). The timing of real processes (a sip takes a second or two, pouring a glass a few seconds; nothing freezes mid-action or completes within a frame; no repeated cycle). Stylised or anime rendering, which changes how things are drawn and never what they do: an anime bottle is still drunk from its spout, three capsules are still three, and the family's sweat drops, speed lines and held frames are allowed where the references use them but are never a reason to accept a count or affordance break. Solidity, collision and occlusion (solid things exclude each other: a tossed crumpled paper never travels through the client's plastic bottle, a ball never through a can, keys dropped on a pack never land inside it, a hand, a sleeve, a strap or hair never through the product, a door never through a person; nothing sinks into a table, a sofa arm or a palm; nothing shows through an opaque body; whatever is nearer the camera hides what is farther, in that order only; a thing that meets a solid stops, deflects, bounces, slides along it or lands on or against it, and what it hits reacts to its weight, so a paper that hits a bottle leaves it standing or rocks it and a hand that hits a can knocks it over; nothing reacts before the contact). Posture, support and place (a flat pack lies flat, nothing leans on a prop the model has to invent, nothing rests on a thin sheet that hands move, the pack sits where a person would leave it, and a placed product never takes a beat of the source). Identity: the swapped face matches the kept body (skin tone, age, build). When the source rides as the video reference the model keeps the performer's body, hands and forearms and replaces only what the identity image names, so a character image is chosen by comparing it with the source performer (a lighter face on a darker body, or the reverse, was once delivered and rejected); the plan states the pick and the match, the prompt says that face, neck, hands and forearms share one skin tone from face to fingertips with an exclusion against a face lighter or darker than the hands, and quality control compares face and hand tone on a full-resolution frame, writing the frame path in the verdict (an unchecked item counts as failed); a mismatch regenerates with no post-fix. Identity reference hygiene: the identity image brings its clothing, lettering, props and open eyes, so it is cropped above the collar when its clothing differs from the kept garment, a print the photo cuts off is cropped away and a plain garment stated, the replacement's glasses are described positively, and a hidden face or closed eyes of the source are stated in words. Each class lists the breaks to expect per product family (cans, capped and straw bottles, glasses, cartons, gum cartons and pouches, capsules, snacks, creams and sprays, phones and earbuds, cars, worn items, appliances), plus the breaks any product suffers near a moving thing.
- **Ledger.** The entity state ledger carries, for every tracked item, its count, its opening or lid state, its level, its holder and hand, the contact point of every use, and whether its anchor is in frame, with one row per event and a visible cause on every row; irreversible states are copied forward to the end. Every thrown, dropped, swung, rolled or carried thing that passes near a tracked object gets a path row (where it starts, the side it passes on or the point where it lands, what it touches, what reacts), and every tracked object an occlusion note for the moments something passes in front of or behind it.
- **Prompt.** Every use beat is written as initial state → operation on the named part → observable result, with the contact point and the body mechanics of that use ("he flips the cap open with his thumb, puts his lips on the spout and drinks through it with his head level, both hands around the bottle; the milk level sinks a little"). Every multiple carries its number at the start, at each event and at the end, and is restated after every exit, occlusion, cut, hand-off and seam ("exactly three capsules lie on the desk to the right of the lamp; they stay there, all three, while he walks past and when he comes back"). Contents are bound to the sample and to the liquid only. Each product gets one targeted exclusion for its own wrong use and count ("he drinks only through the spout; the bottle has no other opening", "exactly three capsules; none appears or disappears"); a generic exclusion list never replaces it. When the model takes images, one view shows the part in its ready state, and no reference image shows a later state than the first frame. Every path is written relative to the solid things it passes, positive first ("he tosses the crumpled paper; it arcs past the bottle on its far side and lands behind it on the desk; the bottle is not touched and does not move", or "the paper hits the can, bounces off and drops to the desk; the can rocks once and settles upright on the same spot"), then the solidity exclusion ("nothing passes through the bottle; it is solid and opaque"); when the story does not need the contact, the product's anchor is moved out of the throw's or the hand's natural path. Each model's guide states how that model phrases these lines in its own structure.
- **Quality-control checkpoints.** The plan lists its checkpoints: every use beat, exit and re-entry, occlusion, cut, hand-off, pour and seam, plus the first and last second, each with its time range and the counts and states expected there. The quality-control tool renders a 30 fps sheet per checkpoint next to the 5 fps storyboard, and the agent views every sheet, counts every multiple at every checkpoint and writes the numbers in its verdict, checks the preparation step, the part used and the contact point on every use beat, measures the product against a hand or face on two or three sheets, checks each person's hands after every hand-off, and compares count, spot, state, size and label orientation before and after every exit, occlusion, cut and seam. At 30 fps wherever anything passes near, in front of or behind the product, lands on it or hits it, the agent checks that the silhouettes never overlap as only a transparent body would allow, that the occlusion order matches the depth, that every contact has its consequence and that nothing reacts before it. A count or state that changes without a cause, a use through a part with no opening or a closed one, an effect before its cause, a reversed irreversible state, a wrong-part body mechanic, a mirrored or migrated label, a stale holder, a lean against nothing, a posture the shape cannot take, a pack touching a working hand or arm, a warped sheet under a pack, and any pass-through, sinking, see-through, wrong occlusion order or hit without a consequence are regenerate reasons; the only post-fixes are a pixel hold on an untouched static anchor in a locked shot, a one-frame trim, or a recolor or punch-in in a locked shot; a small, constant oversize that keeps the label readable may be accepted with a note. The corrected retry names the cause (a missing sentence, a leaking reference image, a parameter), adds the exact line from the class and removes the leak; it never adds timing constraints to free motion. The checkpoints also track the placed product against a fixed neighbour at least every 0.25 s from frame 0, and, once the CapCut project is assembled, the agent views dense sheets of every transition, insert start and end and overlay start and end and of the first second of the final, and checks the audio (the original track one whole segment, proven by a hash or a null test); each production agent writes the evidence path of every such check in its result file and records "not checked: why" for any it could not run, and the main session verifies at each agent report, and again at the wrap-up, that the ledger, the state, the README table, the deliverables, the result file and the plan and brief files are all updated.
- **Growth.** Every newly observed anomaly is added to the catalog as a case of its class, with its ledger entry, prompt line, checkpoint and verdict, so the catalog grows instead of the command.
